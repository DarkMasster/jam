# Офис — прицеливание курсором и стиком

- Владелец: `ИИ-агент`
- Статус: `Done; runtime smoke пропущен по запросу продюсера`
- Приоритет: `P1`
- Ветка: `feature/office-aim-controls`
- Зависимости: `общая карта Office с action Aim`
- Лимит времени: `1 час`

## Цель

Отделить направление взгляда и броска героя от движения: курсор мыши задаёт точку
прицеливания на плоскости офиса, правый стик — направление, а WASD/левый стик только
перемещают героя.

## Контекст

Общая карта `Office` уже содержит `Move`, `Aim`, `Primary`, `Secondary` и
`Interact`, но офисный runtime читает только `Move` и `Primary`. Текущую логику
поворота, автоподбора и броска нужно перевести на единое направление прицеливания,
не меняя правила предметов, Momentum, маршрута или босса.

## Критерии готовности

- [x] Курсор мыши разворачивает героя к точке на плоскости XZ.
- [x] Правый стик геймпада разворачивает героя по направлению отклонения.
- [x] WASD и левый стик перемещают героя, но не меняют направление взгляда.
- [x] Автовыбор предмета и бросок используют направление прицеливания.
- [x] При отсутствии значимого Aim сохраняется последнее направление взгляда.
- [ ] Целевые тесты и Play Mode проходят: пропущены по запросу продюсера.
- [x] Unity компилирует изменения без ошибок.
- [x] `OFFICE_ROADMAP.md` обновлён до Handoff.

## Не менять

- Общие Core API, другие эпизоды, Build Settings и Project Settings.
- Правила движения, Momentum, броска, автоподбора, урона, restart и босса вне
  выбора направления.

## Как проверить

Открыть `Assets/Game/Scenes/Prologue_Office.unity` и запустить Play Mode. Развести
направления движения и прицела: идти WASD в одну сторону, удерживая курсор в другой,
затем повторить с левым и правым стиками. Герой, подсветка цели и бросок должны
следовать Aim, а не Move; после отпускания Aim направление не должно сбрасываться.

## Handoff

- Что сделано: `OfficePlayerController` читает `Office/Aim` отдельно от `Move`.
  Позиция курсора проецируется лучом камеры на плоскость XZ игрока, правый стик
  преобразуется в camera-relative направление. Последний валидный Aim сохраняется,
  WASD/левый стик больше не поворачивают героя. `OfficeCarryController` использует
  то же направление для выбора предмета и броска. Общий `Aim` переведён в
  `PassThrough`, чтобы события правого стика не подавлялись величиной координат
  курсора.
