# Roadmap офисного эпизода

- Тип: живой план реализации и передачи контекста
- Статус: активен
- Последнее обновление: 2026-08-02
- Владелец актуальности: исполнитель текущей офисной задачи
- Текущая контрольная точка: `M7 — визуальный feedback через Damage Numbers Pro`

Документ переводит утверждённый офисный эпизод в последовательность небольших
проверяемых срезов. Он не заменяет `DEVELOPMENT_SPEC.md`, `STORY.md`,
`QUESTIONS.md` и `CONTRACTS.md`: при конфликте работа останавливается, решение
фиксируется в основном источнике правды, а затем отражается здесь.

## Обязательное правило работы

Этот файл обязателен для любой задачи, которая затрагивает офисный эпизод, в том
числе:

- `Assets/Game/Episodes/Office/**` и `Assets/Game/Scenes/Prologue_Office.unity`;
- офисные input actions, сохранение, переходы, checkpoints и результат эпизода;
- предназначенные для офиса art, audio, UI, prefabs, тесты и build-проверки;
- офисный раздел спецификации, сюжет, задачи или веб-референс.

Перед началом такой задачи исполнитель:

1. Читает общие документы в порядке из `AGENTS.md`.
2. Читает этот roadmap целиком непосредственно перед назначенным task-файлом.
3. Сверяет scope задачи с текущей контрольной точкой, зависимостями и правилами
   сокращения ниже.

Перед заполнением `Handoff` исполнитель обязательно редактирует этот файл в той же
ветке:

1. Обновляет состояние затронутого milestone и проверенные факты.
2. Актуализирует блокеры, зависимости и единственный следующий офисный срез.
3. Добавляет строку в `Историю изменений`, даже если статус milestone не изменился.

Офисную задачу нельзя переводить в `Done`, пока roadmap не обновлён. Формулировка
«изменений roadmap не потребовалось» не заменяет правку: минимум должна быть
добавлена запись о проверке и её результате в истории изменений.

## Целевой путь игрока

```text
Setup: герой засыпает в машине у границы
→ быстрый забег по пяти офисным зонам
→ автоподбор и использование офисных предметов
→ разрушение техники поддерживает Momentum
→ обязательный сбор ноутбука и любимой кружки
→ ложная дверь EXIT
→ сборка босса из серверных стоек
→ собранный корпус и ложная победа
→ кольцо из отдельных стоек
→ неизбежный финальный удар
→ пробуждение, Hotel Arrival, сохранение результата
```

Целевая длительность полного эпизода — 5–10 минут. Джем-билд использует один
короткий авторский маршрут, а не процедурный офис.

## Неподвижные границы

- Реального выхода через `EXIT` нет.
- Только финальная неизбежная атака босса успешно завершает эпизод; ранняя смерть
  запускает быстрый restart.
- Противники — ожившая техника, не люди.
- Ноутбук и кружку невозможно пропустить перед финальной зоной.
- Боевые предметы подбираются автоматически; `Interact` остаётся для дверей и
  постановочных объектов.
- Runtime-ввод идёт только через общий `InputSystem_Actions.inputactions`, которым
  владеет интегратор.
- Разрушение ограничено подготовленными состояниями, без свободной фрагментации.
- Веб-демо `web-demos/office/` — референс темпа и game feel, а не кодовый контракт.
- Процедурная генерация, сложная физика кабелей, большой арсенал и дополнительные
  противники не входят в текущий джемовый scope.

## Milestones и критерии приёмки

### M0 — Playable greybox — Done

- [x] Сцена `Prologue_Office` запускается напрямую.
- [x] Маршрут содержит стартовый кабинет, open space, стеклянную переговорную,
      серверную и рецепцию.
- [x] Top-down движение работает через New Input System, камера следует за героем.
- [x] Ноутбук и кружка собираются автоматически; HUD показывает `0/2–2/2`.
- [x] `EXIT` физически закрыт и сообщает состояние цели.
- [x] Scene validation и чистый controlled Play Mode пройдены без ошибок.

### M1A — Один предмет, бросок и простое разрушение — Done

- [x] Один лёгкий или средний предмет автоматически выбирается перед героем и
      показывает цель подбора.
- [x] Занятые руки не заменяют текущий предмет новым.
- [x] `Primary` бросает предмет; краткий lockout не даёт подобрать его в том же
      кадре.
- [x] Один подготовленный объект проходит состояния `Intact → Broken` и даёт
      однозначный визуальный feedback.
- [x] Существующие pickups, маршрут и закрытый `EXIT` не регрессируют.

Реализация: `OfficeCarryable` (клавиатура), `OfficeCarryController` на герое и
`OfficeBreakable` (принтер). Восемь клавиатур и четыре принтера расставлены по
маршруту, чтобы петля проверялась в каждой зоне. Брошенный предмет, вылетевший за
пределы этажа, возвращается на своё место, поэтому зона не остаётся без предмета.

### M1B — Один противник, Momentum и быстрый restart — Done

- [x] Продюсер закрыл `QUESTIONS.md` P0 №7 и №8: противник — офисное кресло, тон —
      смешанный; одновременно разрешён временный технический placeholder, поэтому
      набор техники считается заменяемым без переработки кода.
- [x] Один тип техники имеет читаемый силуэт, красный телеграф и одно поведение.
- [x] Удар, бросок или столкновение повреждает технику через episode-local логику.
- [x] Разрушение и атаки повышают Momentum; простой заметно его снижает.
- [x] Ранняя смерть восстанавливает устойчивое начало забега не дольше чем за пять
      секунд.

Реализация: `OfficeChaser` (prefab `HostileChair`) — цикл `Dormant → Telegraph →
Dash → Recover`, активация по радиусу и прямой видимости, красная полоса телеграфа
длиной с будущий рывок, промах заканчивается ударом о мебель и длинным откатом.
Тело кресла сделано триггером, иначе таран выталкивал героя наверх; попадание
броском идёт через общий `IOfficeImpactTarget`, который реализуют и `OfficeBreakable`,
и `OfficeChaser`. `OfficeMomentum` даёт +26% за разрушение, +34% за списанную
технику и падает 0,055/с в движении против 0,26/с на простое, поднимая скорость до
×1,32 и силу броска до ×1,4. `OfficeRunController` держит три деления
работоспособности, окно неуязвимости 1,2 с и мягкий restart через реестр
`OfficeRunReset`: сцена ещё не в Build Settings, поэтому забег восстанавливается без
её перезагрузки за 1,1 с. После добавления сцены в Build Settings это можно
заменить обычной перезагрузкой.

Красный акцент противника продублирован на сиденье: со штатной top-down камеры
одной полосы на спинке недостаточно, чтобы отличить его от обычного кресла.

### M2 — Авторский маршрут и обязательные личные вещи — Done

- [x] Игрок без отдельного tutorial-экрана понимает движение, предмет, опасность и
      цель `EXIT`.
- [x] Пять зон образуют один короткий темповый маршрут с читаемыми границами.
- [x] Ноутбук и кружка находятся на обязательном пути или имеют гарантированный
      fallback до входа в финальную зону.
- [x] Стеклянная переговорная содержит минимальный Reflection beat или его
      утверждённый визуальный fallback.
- [x] Путь стабильно проходится без soft lock; окончательное время полного эпизода
      балансируется после добавления босса и сюжетных битов `M3–M4`.

Реализация: `OfficeCoach` ведёт одну контекстную строку HUD по цепочке «движение →
автоподбор → бросок → красный телеграф → личные вещи → EXIT» и не повторяет уже
выученные боевые шаги после мягкого restart. `OfficeReflectionBeat` один раз за
забег показывает задержанный холодный силуэт за правым стеклом переговорной и
короткую строку, затем полностью восстанавливается при restart.
`OfficeItemGuarantee` на полном поперечном пороге рецепции переносит только
пропущенные вещи вместе с их напольными маркерами к подходу перед `EXIT` и включает
полноширинный `Access Hold`; пройти дальше можно только после автоматического сбора
ноутбука и кружки. После сбора блокер выключается, а restart возвращает вещи,
маркеры, Reflection и подсказки в устойчивое состояние.

### M3 — Составной серверный босс — Done / P0

- [x] Подход к `EXIT` с двумя предметами запускает короткую управляемую сборку
      босса из нескольких стоек.
- [x] Первая стадия читается как бой с единым корпусом и заканчивается ложной
      победой.
- [x] Стойки зримо расходятся в заранее заданное кольцо без телепортации на героя.
- [x] Во второй стадии управление ненадолго возвращается, но проходимого разрыва в
      кольце нет.
- [x] Механические SFX синхронизированы с разными голографическими репликами.
- [x] Неизбежный финальный удар завершает эпизод; любая более ранняя смерть — нет.

Реализация: `OfficeBossEncounter` управляет последовательностью `Dormant →
Assembling → Assembled → Encircling → RingFight → FinalTelegraph → Completed`.
Двенадцать существующих prefab-стоек сходятся в корпус за 1,8 с, принимают три
попадания через общий `IOfficeImpactTarget`, затем за 1,9 с переходят к заранее
заданным точкам кольца. Во время перестроения герой плавно центрируется внутри
арены, а физические соединители закрывают промежутки между стойками; после четырёх
секунд возвращённого управления общий телеграф покрывает всё кольцо. Сюжетный удар
фиксирует `IsStoryCompleted`, блокирует управление и не запускает restart, тогда
как ранняя смерть сохраняет мягкий restart `M1B`. Внутри арены добавлены три
клавиатуры, поэтому первая стадия не зависит от предмета, принесённого из серверной.
Жужжание и щелчки создаются episode-local процедурно, а RU/EN реплики и HUD-состояния
добавлены в таблицу `Office`.

### M4 — Сюжет, сохранение и общий flow — Done

- [x] Setup объясняет сон в машине без длинной непрерываемой cutscene.
- [x] После финального удара герой просыпается и переходит в `HotelArrival`.
- [x] Checkpoint хранит только устойчивую фазу и episode-owned payload.
- [x] Результат содержит как минимум retries, `hasLaptop` и `hasMug`.
- [x] Эпизод сообщает завершение через общий flow и не загружает чужую сцену
      напрямую.

Реализация: `OfficeStoryDirector` владеет фазами `Setup → Run → Awakening →
Arrival`. Setup и пробуждение показываются storyboard-катсценами
`office.prologue.setup` и `office.prologue.awakening` через общий
`CutsceneDirector`; обе пропускаются, а при отсутствии director'а срез
переключается на короткие HUD-биты и не блокирует управление.
`OfficeCheckpointAdapter` сериализует единственный episode-owned payload схемы `1`
и чинит несогласованные состояния: пробуждение не является границей сохранения, а
`office.arrival` без обеих личных вещей откатывается к `office.run`. Директор также
реализует `IGameModeSaveProvider`, поэтому общий pause-overlay сохраняет офисный
забег только внутри управляемого забега.

Общий слой flow вынесен в Core: `EpisodeResult` с retries, ноутбуком, кружкой,
разрушенной техникой и списанными креслами, `GameFlowService.CompleteEpisode`,
параметризованная сцена `HotelArrival` и `HotelArrivalController`. Офис не знает
имени сцены прибытия. Загрузка `HotelArrival` перезаписывала сцену линии в
сохранении, поэтому `FinishArrival` возвращает checkpoint на сцену эпизода —
иначе повторный выбор героя открывал бы экран прибытия вместо забега. Пройденный
сон при повторном заходе начинается с `Setup` и чистого счёта.

### M6 — Polish — Done

- [x] Добавлены ключевые SFX, попадания, частицы и умеренная дрожь камеры.
- [x] Интенсивность света и красного feedback следует Momentum и не ухудшает
      читаемость пола и телеграфов.
- [x] Голограммы не перекрывают героя, HUD и опасные области.

Реализация: `OfficeFeedback` — episode-local presentation-слой. На каждое
разрушение, попадание, бросок и удар по герою он играет процедурный SFX с
переменной высотой тона, выпускает частицы из пула шести систем в цветах палитры и
запускает дрожь камеры. `OfficeCameraShake` складывается поверх `OfficeCameraFollow`
и снимает собственное смещение, поэтому камера не уезжает; сильный запрос
перекрывает слабый вместо накопления. `OfficeMomentumAmbience` ведёт красные
акценты от Momentum: `1.20 → 2.60` с прогревом к `#FF5A3C`, тогда как холодный
ключевой свет только прибавляет `0.50 → 0.72` и никогда не опускается ниже базы —
пол и красные телеграфы остаются различимыми на любом значении шкалы.
Голограмма босса стоит в `(0.00, 4.25, 38.40)`, то есть выше героя и за кольцом, и
не пересекается ни с полом арены, ни с экранным HUD.

### M7 — визуальный feedback через Damage Numbers Pro — Planned / P1

- [ ] Успешное попадание по креслу или собранному боссу показывает `−1` над целью.
- [ ] Засчитанный урон игроку показывает `−1` над героем.
- [ ] Разрушение принтера показывает короткое уведомление `СЛОМАНО` над объектом.
- [ ] Автоподбор клавиатуры, ноутбука и кружки показывает отлетающий текст над
      героем; сбор обеих личных вещей получает отдельное редкое уведомление.
- [ ] DNP не показывается при слабом, повторном или не засчитанном столкновении.
- [ ] Существующие HUD, SFX, частицы и дрожь камеры сохраняются без регрессий.

Damage Numbers Pro остаётся только presentation-слоем. Игровая система сначала
меняет авторитетное состояние, затем `OfficeFeedback` публикует подтверждённое
семантическое событие через проектный `IGameFeedback`/`GameFeedbackService`, а
DNP-адаптер выбирает один из трёх project-owned preset: `OfficeDamage`,
`OfficeInteraction`, `OfficeMilestone`. Vendor-каталог
`Assets/DamageNumbersPro/**` не редактируется.

Числовое значение фиксируется как `−1`: текущая модель использует скорость удара
только как порог успешного попадания, а не как переменный урон. Обычный impact без
смены состояния не порождает цифру. World-popup остаётся в точке цели; уведомление
о подборе коротко следует за героем и затем уходит вверх. Для всех preset включены
pooling, лимит активных экземпляров и стабильная combination-группа по цели и
категории.

Точки подключения: успешные ветки `OfficeBreakable.TryBreak`,
`OfficeChaser.TryTakeImpact`, `OfficeBossEncounter`,
`OfficeRunController.TryDamagePlayer`, `OfficeCollectible.OnTriggerEnter` и
автоподбор в `OfficeCarryController`. Подключение цифр к безусловному
`OfficeCarryable.ReportImpact` запрещено, иначе слабые столкновения дадут ложный
feedback.

## Порядок сокращения

Если времени не хватает, сокращать в таком порядке:

1. Дополнительные виды врагов и оружия.
2. Призрачное эхо Reflection; оставить визуальный beat у переговорной.
3. Вариации атак, реплик, декора и эффектов.
4. Дополнительные комнаты за пределами обязательного маршрута.

Не вырезать: один законченный action-loop, ноутбук и кружку, ложный `EXIT`, сборку
босса, кольцо, неизбежный финальный удар, пробуждение, сохранение завершения и
переход к Hotel Arrival.

## План визуального прохода POLYGON Office — Planned / P1

Визуальное направление: относительно нормальный тёплый кабинет увольнения
переходит в повторяющийся холодный open space, стеклянную переговорную, плотную

движения офис должен выглядеть всё менее человеческим, но навигационная полоса,
