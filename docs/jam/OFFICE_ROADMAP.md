# Roadmap офисного эпизода

- Тип: живой план реализации и передачи контекста
- Статус: активен
- Последнее обновление: 2026-08-01
- Владелец актуальности: исполнитель текущей офисной задачи
- Текущая контрольная точка: `M1A — предмет, бросок и простое разрушение` завершена; далее `M1B — противник, Momentum и быстрый restart`

Документ переводит утверждённый офисный эпизод в последовательность небольших
проверяемых срезов. Он не заменяет `DEVELOPMENT_SPEC.md`, `STORY.md`,
`QUESTIONS.md` и `CONTRACTS.md`: при конфликте работа останавливается, решение
фиксируется в основном источнике правды, а затем отражается здесь.

## Обязательное правило работы

Этот файл обязателен для любой задачи, которая затрагивает офисный эпизод, в том
числе:

- `Assets/Game/Episodes/Office/**` и `Assets/Game/Scenes/Prologue_Office.unity`;
- офисные input actions, сохранение, переходы, checkpoints и результат эпизода;
- предназначенные для офиса art, audio, UI, prefabs, тесты и build-проверки;
- офисный раздел спецификации, сюжет, задачи или веб-референс.

Перед началом такой задачи исполнитель:

1. Читает общие документы в порядке из `AGENTS.md`.
2. Читает этот roadmap целиком непосредственно перед назначенным task-файлом.
3. Сверяет scope задачи с текущей контрольной точкой, зависимостями и правилами
   сокращения ниже.

Перед заполнением `Handoff` исполнитель обязательно редактирует этот файл в той же
ветке:

1. Обновляет состояние затронутого milestone и проверенные факты.
2. Актуализирует блокеры, зависимости и единственный следующий офисный срез.
3. Добавляет строку в `Историю изменений`, даже если статус milestone не изменился.

Офисную задачу нельзя переводить в `Done`, пока roadmap не обновлён. Формулировка
«изменений roadmap не потребовалось» не заменяет правку: минимум должна быть
добавлена запись о проверке и её результате в истории изменений.

## Целевой путь игрока

```text
Setup: герой засыпает в машине у границы
→ быстрый забег по пяти офисным зонам
→ автоподбор и использование офисных предметов
→ разрушение техники поддерживает Momentum
→ обязательный сбор ноутбука и любимой кружки
→ ложная дверь EXIT
→ сборка босса из серверных стоек
→ собранный корпус и ложная победа
→ кольцо из отдельных стоек
→ неизбежный финальный удар
→ пробуждение, Hotel Arrival, сохранение результата
```

Целевая длительность полного эпизода — 5–10 минут. Джем-билд использует один
короткий авторский маршрут, а не процедурный офис.

## Неподвижные границы

- Реального выхода через `EXIT` нет.
- Только финальная неизбежная атака босса успешно завершает эпизод; ранняя смерть
  запускает быстрый restart.
- Противники — ожившая техника, не люди.
- Ноутбук и кружку невозможно пропустить перед финальной зоной.
- Боевые предметы подбираются автоматически; `Interact` остаётся для дверей и
  постановочных объектов.
- Runtime-ввод идёт только через общий `InputSystem_Actions.inputactions`, которым
  владеет интегратор.
- Разрушение ограничено подготовленными состояниями, без свободной фрагментации.
- Веб-демо `web-demos/office/` — референс темпа и game feel, а не кодовый контракт.
- Процедурная генерация, сложная физика кабелей, большой арсенал и дополнительные
  противники не входят в текущий джемовый scope.

## Milestones и критерии приёмки

### M0 — Playable greybox — Done

- [x] Сцена `Prologue_Office` запускается напрямую.
- [x] Маршрут содержит стартовый кабинет, open space, стеклянную переговорную,
      серверную и рецепцию.
- [x] Top-down движение работает через New Input System, камера следует за героем.
- [x] Ноутбук и кружка собираются автоматически; HUD показывает `0/2–2/2`.
- [x] `EXIT` физически закрыт и сообщает состояние цели.
- [x] Scene validation и чистый controlled Play Mode пройдены без ошибок.

### M1A — Один предмет, бросок и простое разрушение — Done

- [x] Один лёгкий или средний предмет автоматически выбирается перед героем и
      показывает цель подбора.
- [x] Занятые руки не заменяют текущий предмет новым.
- [x] `Primary` бросает предмет; краткий lockout не даёт подобрать его в том же
      кадре.
- [x] Один подготовленный объект проходит состояния `Intact → Broken` и даёт
      однозначный визуальный feedback.
- [x] Существующие pickups, маршрут и закрытый `EXIT` не регрессируют.

Реализация: `OfficeCarryable` (клавиатура), `OfficeCarryController` на герое и
`OfficeBreakable` (принтер). Пять клавиатур и четыре принтера расставлены по
маршруту, чтобы петля проверялась в каждой зоне. Брошенный предмет, вылетевший за
пределы этажа, возвращается на своё место, поэтому зона не остаётся без предмета.

### M1B — Один противник, Momentum и быстрый restart — Next / P0

- [ ] Продюсер закрывает `QUESTIONS.md` P0 №7 и №8 либо явно разрешает временный
      технический placeholder.
- [ ] Один тип техники имеет читаемый силуэт, красный телеграф и одно поведение.
- [ ] Удар, бросок или столкновение повреждает технику через episode-local логику.
- [ ] Разрушение и атаки повышают Momentum; простой заметно его снижает.
- [ ] Ранняя смерть восстанавливает устойчивое начало забега не дольше чем за пять
      секунд.

### M2 — Авторский маршрут и обязательные личные вещи — P0

- [ ] Игрок без отдельного tutorial-экрана понимает движение, предмет, опасность и
      цель `EXIT`.
- [ ] Пять зон образуют один короткий темповый маршрут с читаемыми границами.
- [ ] Ноутбук и кружка находятся на обязательном пути или имеют гарантированный
      fallback до входа в финальную зону.
- [ ] Стеклянная переговорная содержит минимальный Reflection beat или его
      утверждённый визуальный fallback.
- [ ] Путь стабильно проходится за целевое время после короткой балансировки.

### M3 — Составной серверный босс — P0

- [ ] Подход к `EXIT` с двумя предметами запускает короткую управляемую сборку
      босса из нескольких стоек.
- [ ] Первая стадия читается как бой с единым корпусом и заканчивается ложной
      победой.
- [ ] Стойки зримо расходятся в заранее заданное кольцо без телепортации на героя.
- [ ] Во второй стадии управление ненадолго возвращается, но проходимого разрыва в
      кольце нет.
- [ ] Механические SFX синхронизированы с разными голографическими репликами.
- [ ] Неизбежный финальный удар завершает эпизод; любая более ранняя смерть — нет.

### M4 — Сюжет, сохранение и общий flow — P0

- [ ] Setup объясняет сон в машине без длинной непрерываемой cutscene.
- [ ] После финального удара герой просыпается и переходит в `HotelArrival`.
- [ ] Checkpoint хранит только устойчивую фазу и episode-owned payload.
- [ ] Результат содержит как минимум retries, `hasLaptop` и `hasMug`.
- [ ] Эпизод сообщает завершение через общий flow и не загружает чужую сцену
      напрямую.

### M5 — Build-ready — P0

- [ ] `Main → CharacterSelect → Prologue_Office → HotelArrival` проходит в сборке.
- [ ] Цикл длится 5–10 минут и не допускает soft lock.
- [ ] Цель, телеграфы и финальное сюжетное поражение понятны без устного пояснения.
- [ ] Console чиста; сцена не содержит missing scripts/references.
- [ ] Выполнен Windows x64 smoke test и записан результат.

### M6 — Polish — P1 после всех P0

- [ ] Добавлены ключевые SFX, попадания, частицы и умеренная дрожь камеры.
- [ ] Интенсивность света и красного feedback следует Momentum и не ухудшает
      читаемость пола и телеграфов.
- [ ] Голограммы не перекрывают героя, HUD и опасные области.
- [ ] Проведена финальная балансировка и короткий build review.

| Build Settings и переход из `CharacterSelect` | Интегратор | `M4–M5` |
| Save/Flow API и `EpisodeProgressReporter` | Интегратор | `M4` |
| Набор противников и тон кошмара, P0 №7–8 | Продюсер | Контент `M1B–M3` |
| Episode-local сцена, механики и prefabs | Владелец Office | `M1–M3` |
| Setup, Reflection и Arrival | Нарратив + Office | `M2–M4` |
| Голограммы, SFX и feedback | Office + назначенные art/audio владельцы | `M3`, затем `M6` |

Общие ресурсы не редактируются владельцем Office без назначения или согласования.
Если зависимость не готова, episode-local срез сохраняет настраиваемую ссылку или
placeholder и оставляет точную инструкцию интегратору.

## Порядок сокращения

Если времени не хватает, сокращать в таком порядке:

1. Дополнительные виды врагов и оружия.
2. Призрачное эхо Reflection; оставить визуальный beat у переговорной.
3. Вариации атак, реплик, декора и эффектов.
4. Дополнительные комнаты за пределами обязательного маршрута.

Не вырезать: один законченный action-loop, ноутбук и кружку, ложный `EXIT`, сборку
босса, кольцо, неизбежный финальный удар, пробуждение, сохранение завершения и
переход к Hotel Arrival.
